## Defects Found and Fixed

### D-001: ResistanceEstimator bypassed unified GPIO mutation path (P1-004 violation)

| Field | Value |
|---|---|
| **Severity** | HIGH |
| **Phase** | A (Static Control-Path Audit) |
| **Source evidence (before)** | `firmware/ResistanceEstimator.cpp` lines 281, 298 called `Drivers::relay.setChannel(ch, true/false)` directly in `runLoadStepTest()`, BYPASSING `RelayEngine::applyChannelState()`. This created a second physical actuation path, violating P1-004. |
| **Test evidence** | `grep -rn "Drivers::relay.setChannel" firmware/` showed 2 call sites outside RelayEngine: `ResistanceEstimator.cpp:281` (force ON) and `:298` (force OFF) |
| **Fix** | (1) Added `RelayEngine::forceChannelState(idx, newState)` public method that routes through `applyChannelState()` (unified path) + checks safety lockout. (2) Updated `ResistanceEstimator::runLoadStepTest()` to call `Services::relayEngine.forceChannelState()` instead of direct `Drivers::relay.setChannel()`. (3) Added safety lockout check — if `maxOnTimeForced` is active, the test-load force-ON is BLOCKED and the test aborts. |
| **Result** | ✅ PASS — After fix, `grep` confirms only `RelayEngine.cpp:55` (inside `applyChannelState()`) + `RelayDriver.cpp` (the actuator itself) call `setChannel()`. No bypass paths remain. |
| **Remaining action** | Add CI grep assertion to prevent regression. |

### D-002: physicalState=false used to represent UNKNOWN (P1-014 semantic error)

| Field | Value |
|---|---|
| **Severity** | MEDIUM |
| **Phase** | F (State Semantics Audit) |
| **Source evidence (before)** | `firmware/firmware_v4.ino` line 117: `bool relayPhysicalState[NUM_CHANNELS] = {false}` — using `false` to represent "UNKNOWN" is semantically wrong (`false` = OFF, not UNKNOWN). `StatusHandlers.h` did not serialize the new state architecture fields at all. |
| **Test evidence** | `grep "physicalState" StatusHandlers.h` returned empty — fields tracked internally but never emitted to PWA. |
| **Fix** | (1) `StatusHandlers.h` now serializes `desiredState`, `reportedState`, `physicalState` (nullable — `null` when `stateConfidence != VERIFIED`), `stateConfidence`, `stateSequence`, `stateTimestamp`, `fault`, `safetyLockoutState`. (2) When `relayStateConfidence[i] != StateConfidence::Verified`, `physicalState` is emitted as `nullptr` (JSON null), NOT `false`. (3) PWA `Channel` type extended with optional fields matching the firmware contract. |
| **Result** | ✅ PASS — PWA `bunx tsc --noEmit` confirms types match. Firmware syntax check confirms serializer compiles. |
| **Remaining action** | PWA UI rendering of `physicalState: null` as "UNKNOWN" badge (future UI enhancement). |

### D-004: Command sequence / stale command protection missing (P1-019)

| Field | Value |
|---|---|
| **Severity** | HIGH |
| **Phase** | C (Command Ordering) |
| **Source evidence** | `CommandArbiter::processCommand()` checks `requestId` (duplicate detection) but has no `commandSequence` field. If MQTT reorders packets (OFF seq=101 arrives before ON seq=100), the later-arriving ON command would execute, resulting in ON when operator wanted OFF. |
| **Fix** | Documented in `CONTROL_SEMANTICS_MATRIX.md` — `commandSequence` semantics defined. Firmware implementation deferred to v4.3.2 (requires TransactionJournal schema change — breaking protocol change). Current `requestId` dedup handles duplicate detection; stale command detection requires the new sequence field. |
| **Result** | 🟡 DOCUMENTED — Architecture defined, firmware implementation pending (requires protocol v5). |
| **Remaining action** | Add `commandSequence` field to `CommandRequest` + reject stale commands in `CommandArbiter::processCommand()`. |

### D-007: Safety state machine incomplete — ACK auto-cleared lockout (P1-003 semantic)

| Field | Value |
|---|---|
| **Severity** | HIGH |
| **Phase** | D (Safety State Machine) |
| **Source evidence (before)** | `SafetySupervisor::acknowledgeSafetyAlarm()` (v4.3.0) directly cleared `maxOnTimeForced` — ACK = CLEAR. Per ChatGPT audit: "Acknowledgement ≠ permission. ACK = operator mengetahui alarm. Bukan: acknowledgement = sistem otomatis boleh menghidupkan relay." |
| **Fix** | NEW: `SafetyLockoutState` enum (NORMAL/TRIPPED/ACKNOWLEDGED/CLEARED/ARMED). `acknowledgeSafetyAlarm()` now transitions TRIPPED → ACKNOWLEDGED (lockout STILL ACTIVE, relay still forced OFF). NEW `clearSafetyLockout()` transitions ACKNOWLEDGED → CLEARED (NOW clears maxOnTimeForced). `armForNormalOperation()` transitions CLEARED → ARMED → NORMAL (auto in tick). `checkMaxOnTimeExceeded()` now sets state=TRIPPED. |
| **Result** | ✅ PASS — State machine implemented. Firmware syntax check confirms. |
| **Remaining action** | Add REST endpoint `/api/safety/acknowledge` + `/api/safety/clear` for PWA to call. |
