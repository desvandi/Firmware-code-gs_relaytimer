# Security Model — Timer Digital Relay v4.3.8

> Implements the security requirements from the Industrial-Grade Implementation
> Directive §32, §34, §49-56, §80-83, §88.

---

## 1. Threat Model

| Threat | Mitigation | Audit brief § |
|---|---|---|
| Credential theft from firmware binary | No hardcoded secrets in repository; all secrets in NVS at runtime, generated per-device at first boot | §32, §51 |
| Replay attack on REST/MQTT commands | `requestId` per command + NVS-backed TransactionJournal dedup (15-min TTL) | §26, §53 |
| Replay attack on GAS POST | HMAC-SHA256 over canonical = `timestamp + "\n" + nonce + "\n" + deviceId + "\n" + body`, ±5-min timestamp tolerance, nonce replay cache (10-min TTL), atomic via LockService | §53, §54 |
| Cross-device MQTT access | Per-device MQTT username/password + ACL (broker-enforced). PRODUCTION_BUILD flag enforces TLS port (8883/8884) + non-empty username + non-empty password + non-empty root CA + non-wildcard CORS | §34, §80 |
| Cross-device GAS access | Each device has its own `DEVICE_<anonymousId>_SECRET` in Script Properties; HMAC validates device identity | §52 |
| OTA downgrade attack | Anti-downgrade check in `OtaManager` — refuses to install older version | §49 |
| OTA signature forgery | Ed25519 signature verification (over SHA-256 of binary, not full binary due to ESP32 RAM constraints). Public key embedded in `Config.h::OTA_ED25519_PUBLIC_KEY_HEX` | §49 |
| OTA malicious URL | Allowlist of trusted hosts (`Config.h::OTA_ALLOWED_HOSTS`) + HTTPS with root CA validation | §49 |
| Prompt injection via telemetry | All device-supplied data wrapped in `<UNTRUSTED_DATA>` markers; system instructions explicitly forbid interpreting wrapped content as commands; field-level sanitization strips angle brackets + backticks | GAS §P1-23 |
| CSRF on REST mutations | Per-session CSRF token cookie + `X-CSRF-Token` header validation on all state-changing requests | §56 |
| XSS via telemetry rendering | React escapes by default; no `dangerouslySetInnerHTML` on device data | §56 |
| Brute-force auth | Per-IP rate limiter: 5 fails → 1-min block; 10 fails → 5-min block | §32 |
| JWT secret leak | Generated per-device at first boot, stored in NVS, not in repo | §32, §51 |
| Device hijack (factory reset abuse) | Factory reset requires two-step prepare+confirm with 60-s TTL token | §41 |

## 2. Authentication Layers

```
┌─────────────────────────────────────────────────┐
│ L1: PWA Browser ↔ ESP32 REST                    │
│    - JWT HS256 (15-min access, 7-day refresh)   │
│    - CSRF cookie + X-CSRF-Token header          │
│    - PBKDF2-SHA256 password hash (10k iters)     │
│    - Per-IP rate limiter                          │
├─────────────────────────────────────────────────┤
│ L2: ESP32 ↔ MQTT Broker                         │
│    - TLS (port 8883/8884) + root CA validation  │
│    - Per-device username/password (broker ACL)  │
│    - Topic ACL: device can only publish/subscribe│
│      its own topics (timer12/<mac>/*)            │
├─────────────────────────────────────────────────┤
│ L3: ESP32 ↔ GAS Web App                        │
│    - HMAC-SHA256 (deviceSecret, canonical)      │
│    - Canonical = ts + "\n" + nonce + "\n" +     │
│      deviceId + "\n" + rawBody                  │
│    - ±5-min timestamp tolerance                 │
│    - Nonce replay cache (10-min TTL, atomic via │
│      LockService.getScriptLock())                │
│    - Per-device rate limit (10 posts/hour)        │
├─────────────────────────────────────────────────┤
│ L4: ESP32 ↔ OTA Source (GitHub Releases)       │
│    - HTTPS with root CA validation              │
│    - URL allowlist (OTA_ALLOWED_HOSTS)          │
│    - SHA-256 hash verification                  │
│    - Ed25519 signature verification             │
│    - Anti-downgrade check                       │
└─────────────────────────────────────────────────┘
```

## 3. Secret Management

All secrets live OUTSIDE the repository (brief §51):

| Secret | Storage | Generated by | Rotation |
|---|---|---|---|
| JWT signing key | NVS `jwt_secret` (32 bytes) | ESP32 at first boot (CSPRNG) | Manual: factory reset → reboot |
| MQTT broker password | NVS `mqtt_pass` (8 chars) | ESP32 at first boot (CSPRNG) | Manual: NVS write + broker update |
| Device PIN (6-digit) | NVS `device_pin` | ESP32 at first boot | PWA Settings → Change PIN |
| GAS HMAC secret | NVS `gas_secret` (32 bytes) | ESP32 at first boot | Manual: regenerate + update GAS Script Properties |
| Ed25519 OTA private key | Owner's signing machine (NOT in firmware) | `scripts/sign_firmware.py --gen-keys` | Regenerate + reflash public key in `Config.h` |
| WiFi SSID/password | NVS `wifi_ssid`, `wifi_pass` | User via WiFi Config Portal | Config Portal on next boot |
| PWA JWT secret (mock mode) | Env var `JWT_SECRET` (Vercel) | Owner | Vercel env update + redeploy |

## 4. Production vs Development Mode

The `PRODUCTION_BUILD` compile flag (defined in `platformio.ini` env:production)
enforces fail-closed behavior (brief §80, §81):

| Check | Development | PRODUCTION_BUILD |
|---|---|---|
| MQTT port | 1883 (plain) | 8883/8884 (TLS) — **HARD FAIL** otherwise |
| MQTT username | Optional | **REQUIRED** — refuse to boot if empty |
| MQTT password | Optional | **REQUIRED** — refuse to boot if empty |
| MQTT root CA | setInsecure() allowed | **REQUIRED** (PEM) — refuse to boot if empty |
| CORS origin | `*` allowed | **NON-WILDCARD** required |
| OTA public key | Optional | **REQUIRED** — refuse to boot if empty |
| OTA HTTPS root CA | Optional | **REQUIRED** — refuse to boot if empty |
| Mock auth (PWA) | Disabled in production | N/A (PWA side) |

If any production check fails, the firmware prints a FATAL message to Serial
and refuses to initialize MQTT — no plaintext fallback, no insecure shortcut.

## 5. Audit Log Events (brief §61)

All security-relevant events are persisted to the LittleFS-backed audit log
(rotates at 8 KB):

| Event | Trigger |
|---|---|
| `Login` | Successful PWA login |
| `AuthFail` | Failed login attempt (rate-limited) |
| `Logout` | PWA logout |
| `RelayOn` / `RelayOff` | Physical relay state change (with source) |
| `ConfigChange` | Any config modification |
| `FactoryReset` | Two-step factory reset completed |
| `Ota` | OTA update started / success / failed / rollback |
| `TimeSync` | RTC time set |
| `Restart` | System boot |

Audit log entries include: `id`, `timestamp` (Unix epoch from RTC),
`type`, `channelId` (if applicable), `message` (truncated to 96 chars).

**Never logged:** passwords, JWT tokens, HMAC secrets, MQTT credentials,
CSRF tokens (brief §61 "Jangan log secrets").
